# Media Merge（多版本合并）

Emby 插件：把 **TMDB 相同、但路径不同** 的重复电影条目合并成一条多版本记录（Emby 的 Multi-Version）。
典型场景：同一部电影既在「华语电影」又在「外语电影」，或不同分辨率/片源各入了一份，刮削后变成两条重复海报。

- 插件 Id：`a3d19c74-2f8b-4e57-8a61-5c9e0b4d7f22`
- 插件名：`Media Merge (多版本合并)`
- 日志前缀：`[MediaMerge]`
- 计划任务：`媒体库 → 多版本合并扫描`（Key `MediaMergeScan`）

## 工作原理

1. 遍历电影条目，按 TMDB Id 分组成候选集合（无 TMDB 的条目跳过）；
2. 逐组过滤：库白名单、排除的 TMDB、仅片名一致、仅同库等开关；
3. 组内为主条目打分（观看记录 / 收藏 / 分辨率偏好 / 海报与命名规范），选出主条目；
4. 通过进程内 `ILibraryManager.MergeItems` 把其余条目并为主条目的多版本；
5. 每组结果写入报告与 `merge_history.jsonl`，含 itemId、路径、决策原因。

**只改库内条目关联**：不移动、不重命名、不删除任何文件；合并后可在 Emby 详情页「拆分版本」还原
（插件对分片文件 `cd1/cd2` 类条目额外做了跳过处理，避免误合并）。

## 触发方式

| 方式 | 说明 |
| --- | --- |
| 手动任务 | 控制台 → 计划任务 → 「多版本合并扫描」→ 运行 |
| 事件驱动 | 订阅 `ItemAdded`，新条目入库去抖 N 秒后，若与已有条目 TMDB 相同则合并 |
| 定时增量 | 可选兜底，按周期处理近期入库造成的重复 |

## 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | `true` | 关闭后事件与增量都不处理，计划任务仍可手动跑 |
| 干跑模式（只出报告不改库） | `true` | 只统计与写报告，不合并。**首次务必保持开启** |
| 单次最多合并组数 | `20` | 0 表示不限制，用于灰度 |
| 仅合并片名一致的组 | `true` | 片名有差异的组只进报告，人工确认 |
| 仅同库合并 | `true` | 跨库重复不在本插件处理 |
| 优先保留有观看记录的条目 | `true` | 避免用户播放进度/收藏丢失 |
| 优先保留的分辨率 | `auto` | `auto` / `2160p` / `1080p` / `720p` |
| 媒体库名称白名单 | 空 | 逗号分隔，留空表示全部 |
| 排除的 TMDB ID | 空 | 逗号分隔，规避已知误配 |
| 新条目入库自动合并 | `true` | ItemAdded 事件驱动 |
| 事件去抖等待（秒） | `10` | 避开一次入库的多条事件 |
| 定时增量扫描 | `false` | 兜底开关 |
| 增量扫描周期（分钟） | `60` | 最小 10 |
| 报告展示组数 | `200` | 0 表示全部 |
| 诊断 TMDB ID | 空 | 填 TMDB 后启动时打印该片所有条目明细 |

## 报告与日志

- 报告目录：插件数据目录 `EmbyMediaMerge/`（容器内通常为 `/config/plugins/EmbyMediaMerge/`，取决于部署方式）
- 报告文件：`report_<yyyyMMdd_HHmmss>_<trigger>.md`，trigger 取 `startup` / `manual` / `itemadded` / `incremental`
- 历史记录：同目录 `merge_history.jsonl`，每行一条合并决策（含 itemId 与路径，**含隐私信息，请勿直接公开**）
- 日志：过滤 `[MediaMerge]`，每轮输出 `groups / merged / report`

## 上线流程建议

1. `干跑模式=true`，跑一次手动任务，检查报告分组是否符合预期（尤其是「仅同库合并」关闭时）；
2. 对报告里的异常分组，把对应 TMDB 填进「排除的 TMDB ID」；
3. 小批量试跑：`干跑模式=false` + `单次最多合并组数=5`，抽查 5 组的详情页多版本是否正常；
4. 确认无误后放开组数上限；
5. **操作前备份 `config/data/library.db`**（合并写库，不可由卸载插件撤销）。

## 已知限制

- 只处理电影，不含剧集；
- 依赖条目已有 TMDB Id，未刮削条目不会参与；
- 同一影片被误刮成同一 TMDB 时会被判为重复，属「排除的 TMDB ID」适用范围；
- 合并后主条目名称取自主条目，若主条目命名较差别名，可在 Emby 内手工改，或用「优先保留的分辨率」调整主条目选择。
