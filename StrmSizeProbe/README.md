# Strm Size Probe

Emby 插件：扫描 `.strm` 媒体项，用 HTTP 请求探测其指向的真实文件大小，并按配置写回 Emby 的 `Size` 字段，
让详情页 / 列表页显示正确体积（Emby 原生对 `.strm` 只读体积为 0 / 未知）。

- 插件 Id：`7f3c1a9e-4b62-4f1d-9a3e-2c8d5b7e6a10`
- 插件名：`Strm Size Probe`（配置页标题「Strm Size Probe 设置」）
- 日志前缀：`[StrmSize]`
- 计划任务：`媒体库 → Strm 大小扫描`（Key `StrmSizeProbe`）

## 工作原理

1. 遍历媒体库中的 `Video` 条目，筛选 `.strm` 路径；
2. 读取 strm 文件内容得到真实 URL（支持多行取首个非空、`#` 注释行）；
3. 先发 `HEAD`，服务端不支持或返回无 `Content-Length` 时改用 `GET` + `Range: bytes=0-0` 读 `Content-Range` 总长；
4. 跟随跳转、支持自定义 UA、按配置重试与超时；
5. 结果写报告；仅在 `WriteToLibrary=true` 时回写 `Size` 字段。

**只读源文件，不下载完整内容**（Range 只取 0 字节），不移动、不删除任何文件。

## 触发方式

| 方式 | 说明 |
| --- | --- |
| 启动扫描 | 服务启动后自动执行一次全量扫描（受「单次扫描条数」限制） |
| 手动任务 | 控制台 → 计划任务 → 「Strm 大小扫描」→ 运行 |
| 事件驱动 | 订阅媒体库 `ItemAdded`，新 strm 入库后去抖 N 秒自动探测，只处理 Size 为空/0 的条目 |
| 定时增量 | 可选开关，按周期按入库时间倒序补最近条目，兜底事件漏单 |

## 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | `true` | 关闭后不自动扫描 |
| 启动时自动扫描 | `true` | 启动后跑一次 |
| 并发数 | `4` | 同时探测的 HTTP 连接数，建议 4-8 |
| 单条超时（秒） | `15` | 单次请求超时 |
| 单次扫描条数 | `50` | 0 表示不限制；全库补齐可设 `100000` |
| 媒体库名称 | 空 | 逗号分隔，留空表示全部媒体库 |
| 写入媒体库 | `false` | 写回 `Size` 字段，默认关闭仅出报告 |
| 仅补齐缺失值 | `true` | 只写 Size 为空/0 的条目，已有值不覆盖 |
| 单次最多写入条数 | `0` | 0 表示不限制，用于分批灰度 |
| 小于该值标记异常（MB） | `100` | 报告中标为可疑 |
| 新条目入库自动探测 | `true` | ItemAdded 事件驱动 |
| 事件去抖等待（秒） | `8` | 入库后等待再探测 |
| 事件队列上限 | `200` | 超出丢弃并记日志 |
| 定时增量扫描 | `false` | 兜底开关 |
| 增量扫描周期（分钟） | `15` | 最小 5 |
| 每轮增量条数 | `500` | 按入库时间倒序检查最近条目 |
| 诊断条目ID | 空 | 填 ItemId 后启动时打印该条目 Size/MediaSources 明细 |

## 报告与日志

- 报告目录：`<Emby data>/EmbyStrmSize/`（容器内通常为 `/config/data/EmbyStrmSize/`）
- 日志：Emby 日志中过滤 `[StrmSize]`，含每轮 `files / ok / fail / written / skipped` 统计

## 建议使用姿势

1. 首次保持 `写入媒体库=false`，跑一次「Strm 大小扫描」，看报告里 `fail` 与可疑条目比例；
2. 网盘限流明显时下调并发到 2-3、超时加到 30s；
3. 报告正常后开启写入，并保留「仅补齐缺失值」，偏好少量灰度可设 `单次最多写入条数=500`；
4. 大批量入库前可临时关闭「新条目入库自动探测」，避免瞬时跑满队列。

## 已知限制

- Emby 后续对条目重新刮削 / 刷新元数据时可能重算 `Size`，需再次运行任务补齐；
- 依赖服务端返回 `Content-Length` / `Content-Range`，部分网盘直链两者都不给时无法探测（记为 fail）；
- 只处理 `.strm`，不处理直链挂载的普通视频文件；
- 需要 Emby 自身刷新条目缓存，个别客户端需重新进入影片详情页才能看到新大小。
